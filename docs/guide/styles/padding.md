# padding-утилиты

Набор из 330 CSS-классов для внутренних отступов. Именование как в Tailwind,
но это обычный статический CSS: ни сборщика утилит, ни рантайма, ни сканирования
исходников. Файл `src/app/styles/utils/padding.css` целиком генерируется скриптом.

> **Про префикс в примерах.** Ниже классы записаны без префикса — `p-4`, `px-6`.
> Сейчас файлы сгенерированы с `--prefix cost-`, поэтому в разметке они
> называются `cost-p-4`, `cost-px-6`. Проверить текущий префикс можно в шапке
> самого CSS-файла, строка «Сгенерировано».

---

## Генерация

```bash
npm run styles:padding                            # .p-4 = 16px
npm run styles:padding -- --prefix cost-          # .cost-p-4
npm run styles:padding -- --step 2                # .p-4 = 8px
npm run styles:padding -- --prefix cost- --step 2
```

Скрипт: `scripts/css/generate-padding.mjs`, общая часть — в `scripts/css/_shared.mjs`.
Чистый Node, без зависимостей. Результат: `src/app/styles/utils/padding.css`
(перезаписывается целиком).

> **Файл руками не правят.** Любая правка исчезнет при следующей генерации.
> Нужен новый класс или другое значение — меняйте генератор.

### Чем padding отличается от margin

В наборе **нет** отрицательных классов и **нет** `auto`:

- отрицательного padding не существует — свойство не принимает такие значения;
- `padding: auto` — невалидный CSS, браузер такое правило просто отбросит.

Поэтому здесь 330 классов против 720 у margin: только 11 сторон × 30 ступеней
шкалы. Нужен «вылет» элемента наружу — это отрицательный margin, `-mx-6`.

### Шаг шкалы

Значение считается как **число в классе × шаг**. Шаг задаётся флагом `--step`,
по умолчанию 4px:

| класс  | `--step 4` | `--step 2` |     | класс         | `--step 4` | `--step 2` |
| ------ | ---------- | ---------- | --- | ------------- | ---------- | ---------- |
| `-0`   | 0          | 0          |     | `-9`          | 36         | 18         |
| `-px`  | 1          | 1          |     | `-10`         | 40         | 20         |
| `-0.5` | 2          | 1          |     | `-11`         | 44         | 22         |
| `-1`   | 4          | 2          |     | `-12`         | 48         | 24         |
| `-1.5` | 6          | 3          |     | `-14`         | 56         | 28         |
| `-2`   | 8          | 4          |     | `-16`         | 64         | 32         |
| `-2.5` | 10         | 5          |     | `-20`         | 80         | 40         |
| `-3`   | 12         | 6          |     | `-24`         | 96         | 48         |
| `-3.5` | 14         | 7          |     | `-28`         | 112        | 56         |
| `-4`   | 16         | 8          |     | `-32`         | 128        | 64         |
| `-5`   | 20         | 10         |     | `-40`         | 160        | 80         |
| `-6`   | 24         | 12         |     | `-48`         | 192        | 96         |
| `-7`   | 28         | 14         |     | `-56` / `-64` | 224 / 256  | 112 / 128  |
| `-8`   | 32         | 16         |     | `-80` / `-96` | 320 / 384  | 160 / 192  |

`-px` — ровно 1 пиксель независимо от шага. `-0` — ноль без единиц.

Шаг у flex, margin и padding задаётся независимо, но держать их разными —
плохая идея: `gap-4`, `m-4` и `p-4` перестанут означать одно и то же.
Меняете шаг — прогоняйте все три генератора с одинаковым `--step`.

## Справочник классов

| префикс | CSS-свойство           | что задаёт                               |
| ------- | ---------------------- | ---------------------------------------- |
| `p-*`   | `padding`              | все четыре стороны                       |
| `px-*`  | `padding-inline`       | слева и справа                           |
| `py-*`  | `padding-block`        | сверху и снизу                           |
| `pt-*`  | `padding-top`          | сверху                                   |
| `pr-*`  | `padding-right`        | справа                                   |
| `pb-*`  | `padding-bottom`       | снизу                                    |
| `pl-*`  | `padding-left`         | слева                                    |
| `ps-*`  | `padding-inline-start` | начало строки: слева в LTR, справа в RTL |
| `pe-*`  | `padding-inline-end`   | конец строки                             |
| `pbs-*` | `padding-block-start`  | начало блока, зависит от `writing-mode`  |
| `pbe-*` | `padding-block-end`    | конец блока                              |

Каждый префикс идёт по всей шкале: `p-0`, `p-px`, `p-0.5`, `p-1` … `p-96`.

Порядок в файле — сверху вниз по этой же таблице. Значит более конкретный класс
перебивает более общий: `class="p-4 pt-8"` даст 32px сверху и 16px с остальных
сторон, потому что `pt-*` идёт ниже `p-*`.

## Типовые приёмы

### Карточка

```html
<article class="p-6">
  <h3>Заголовок</h3>
  <p class="mt-2">Текст карточки.</p>
</article>
```

### Кнопка: разный отступ по осям

```html
<button class="px-4 py-2">Сохранить</button>
```

По горизонтали примерно вдвое больше, чем по вертикали — стандартная пропорция
для кнопок и полей ввода.

### Секция с растущими полями

```html
<section class="px-4 py-16">…</section>
```

На мобильном 16px по бокам. Дальше — вручную через media-запрос, генератор
адаптивных вариантов не делает:

```css
@media (min-width: 48rem) {
  .md\:px-6 {
    padding-inline: 24px;
  }
}
```

### Место под иконку в поле ввода

```html
<div class="flex items-center">
  <svg width="16" height="16" />
  <input class="ps-9 pe-3 py-2" />
</div>
```

`ps-9` — это 36px: 16px под иконку плюс отступы по 10px. Логические `ps`/`pe`
вместо `pl`/`pr` — чтобы в RTL иконка и отступ поменялись местами сами,
без второго набора правил.

### Отступы, зависящие от направления письма

```html
<div class="flex items-center ps-3 pe-4">
  <span class="me-2">Метка</span>
  <span>Значение</span>
</div>
```

## Грабли

**`box-sizing: border-box`.** В `app.css` он включён глобально через `*`,
поэтому padding не увеличивает заданную ширину, а съедает её изнутри. Блок
шириной 200px с `p-6` оставит под контент 152px. Без этого правила поведение
было бы обратным — не полагайтесь на него в отрыве от проекта.

**Отрицательного padding не бывает.** `-p-4` в наборе нет и быть не может.
Если нужно вытащить элемент за границы родителя — это отрицательный margin:
`-mx-6` из `margin.css`.

**Порядок правил важнее порядка в атрибуте.** Все классы одной специфичности,
поэтому выигрывает тот, что **ниже в файле**. Порядок сторон в `padding.css`:
`p`, `px`, `py`, `pt`, `pr`, `pb`, `pl`, `ps`, `pe`, `pbs`, `pbe`.
Отсюда два следствия:

- `class="p-4 pt-8"` работает как ожидается — 32px сверху, 16px по краям;
- `class="ps-3 px-6"` **не** работает как ожидается — `ps-*` идёт ниже `px-*`,
  поэтому слева останется 12px, а не 24px, как бы вы ни переставили классы
  в атрибуте.

**Padding на инлайновом элементе не раздвигает строку.** По вертикали он
нарисуется, но высоту строки не изменит и наедет на соседние строки. Нужен
`display: block`, `inline-block` или флекс-контейнер.

**Не путайте с `gap`.** Отступ _между_ элементами списка — это `gap-*` на
контейнере, а не `py-*` на каждом ребёнке: во втором случае сверху и снизу
списка появятся лишние поля, а между соседями отступ удвоится.

**Опечатку никто не поймает.** Несуществующий `p-13` просто ничего не сделает —
это статический CSS, а не Tailwind со сканированием исходников.
