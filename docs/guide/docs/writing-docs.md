# Как писать доки

Сайт собран на [Rspress 2](https://rspress.rs/) — том же Rsbuild и Rspack,
что и приложение. Никакого второго сборочного стека в проекте не появилось.

## Где что лежит

```
docs/
├── _nav.json            верхнее меню сайта
├── index.md             главная (pageType: home)
├── _shared/             компоненты и стили для .mdx — НЕ страницы
│   ├── global.css
│   ├── Demo.tsx
│   └── FlexPlayground.tsx
├── guide/
│   ├── _meta.json       порядок и подписи в сайдбаре
│   └── *.md
├── styles/
│   ├── _meta.json
│   ├── flex.mdx
│   └── *.md
└── public/              статика: /logo.png → docs/public/logo.png
```

## Маршруты

Путь файла = путь страницы. `guide/structure.md` → `/guide/structure`,
`guide/index.md` → `/guide/`.

Всё, что начинается с `_`, страницей не становится — так работает
`route.excludeConvention` по умолчанию. Поэтому `_shared/` и лежит с
подчёркиванием: это склад компонентов, а не раздел документации.

## Сайдбар

`_meta.json` в папке задаёт порядок и подписи. Без него Rspress соберёт
сайдбар сам, по алфавиту — почти всегда не то, что нужно.

```json
[
  { "type": "file", "name": "index", "label": "Обзор" },
  { "type": "file", "name": "flex", "label": "flex", "tag": "mdx" },
  { "type": "divider" },
  { "type": "dir", "name": "advanced", "label": "Продвинутое", "collapsed": true }
]
```

Короткая форма тоже работает: строка `"install"` равна
`{ "type": "file", "name": "install" }`.

## .md или .mdx

Обычный Markdown кладите как `.md` — ничего настраивать не нужно.
`.mdx` берите, когда на странице должен быть **живой** пример: MDX
компилируется в React-компонент, поэтому в нём работают импорты и JSX.

```mdx
import { FlexPlayground } from '../_shared/FlexPlayground'

# flex

<FlexPlayground />
```

Импортировать можно и настоящие компоненты приложения — алиас `@` настроен
в `rspress.config.ts`:

```mdx
import { EChart } from '@/components/base'
```

:::warning Осторожно с импортами из приложения
Всё, что компонент тянет за собой, попадёт в бандл документации. Компонент,
завязанный на `queryClient`, роутер или `AppGate`, отдельно от приложения
просто не отрисуется. Для доков лучше писать тонкие обёртки в `_shared/`.
:::

## Стили в примерах

`docs/_shared/global.css` импортирует **реальные** сгенерированные утилиты
из `src/app/styles/utils/`. Копии классов нет: перегенерировали
`npm run styles:flex` — доки сразу показывают новое.

`app.css` с токенами тёмной темы приложения намеренно не подключён — у
Rspress своя светлая/тёмная тема, токены бы с ней подрались. Для песочниц
заведены отдельные переменные `--demo-*`, они переключаются по `:root.dark`.

## Полезное в разметке

Блоки-выноски:

```md
:::tip Подсказка
Текст
:::
```

Бывают `tip`, `note`, `info`, `warning`, `danger`, `details`.

:::tip Так это выглядит
Заголовок после типа блока необязателен.
:::

Подсветка строк в коде:

````md
```ts {2-3}
const a = 1
const b = 2
const c = 3
```
````

## Проверка перед коммитом

```bash
npm run docs:build
```

Сборка падает на битых внутренних ссылках — в Rspress 2 проверка мёртвых
ссылок включена по умолчанию. Это и есть основной тест документации.
